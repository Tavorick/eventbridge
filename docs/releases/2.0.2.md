# EventBridge 2.0.2

## Key changes

- Manual Fluent Booking conversions now represent the original website booking with `action_source=website` and a canonical first-party `event_source_url`.
- The immutable booking attribution snapshot now carries the booking-page URL and the freshly captured visitor IP address and user agent. A selected-touch URL is used only as a provenance-preserving fallback.
- New manual website occurrences fail closed when their URL or required booking-time user agent is unavailable; EventBridge never substitutes the later wp-admin request context.
- Existing persisted website, `phone_call`, and `other` occurrences remain immutable and retryable for backward compatibility.
- Privacy-safe outbound diagnostics expose only field-presence and delivery metadata, not raw identifiers, request bodies, tokens, or customer hashes.
- Booking-time IP address and user agent are handed directly from the Fluent request to the booking snapshot without shared profile storage, removed from the snapshot and stored occurrence after confirmed delivery, and redacted from unfinished historical conversion records after 30 days.
- EventBridge admin pages now share consistent primary navigation.

## Payload contract

- Session-booking events retain their configured event names; they are not converted into `Purchase` events.
- No `order_id`, `contents`, `value`, `currency`, `store_data`, or `physical_store` data is invented.
- Meta test-event codes remain top-level request fields and are omitted outside configured test mode.

## Validation

- The final intercepted request-body contract passed on PHP 7.4 and PHP 8.3.
- The complete isolated regression matrix passed on PHP 7.4 and PHP 8.3, including Fluent Booking, WooCommerce classic and HPOS, browser harnesses, WordPress 5.8 compatibility, privacy scanning, source integrity, and safe teardown.
- A fresh staging website booking was recognized by Meta Test Events, externally confirming the corrected website-event contract.
- Release candidate `v2.0.2-rc.1` was published with verified artifacts before this stable promotion.

## Upgrade

- No database migration is required; `EVENTBRIDGE_DB_VERSION` remains 7.
- WordPress 5.8 and PHP 7.4 remain the minimum supported versions.
- Production upgrades should use the verified release ZIP and retain the previous package for rollback.
