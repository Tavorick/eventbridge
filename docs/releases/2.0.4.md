# EventBridge 2.0.4

## Key changes

- Safely reconstructs a missing legacy Fluent Booking attribution snapshot only when the stored booking-time website context has sufficient provenance and valid timestamps.
- Keeps invalid snapshots and insufficient legacy context fail-closed: no occurrence is created and no Meta request is started.
- Stores successful recovery atomically and fill-once, preserving existing or successful deliveries and preventing duplicate dispatch during repeated actions.
- Adds allowlisted, action-oriented feedback for temporary, permanent and non-recoverable conversion failures on both **Conversies** and **Telefoonafspraken**.
- Shows retry actions only for genuinely retryable deliveries; permanent failures are marked as unsafe to process.
- Shows the standalone **Telefoonafspraken** page only while Fluent Booking is active and fully available.

## Security and privacy

- Recovery never uses the current administrator or therapist request IP address or user agent.
- Only a valid IP address stored on the original Fluent booking may be included; mutable profile IP data is never used as fallback.
- Cookies, touches, source URLs and user-agent context are accepted only through the strict allowlist and timestamp policy.
- Therapist feedback contains no internal delivery codes, tokens, PII, cookies, IP addresses, user agents or raw payloads.
- Exact `host_user_id` ownership enforcement remains unchanged.

## Validation

- The canonical isolated matrix passed on PHP 7.4 and PHP 8.3, including synthetic Fluent Booking-to-Meta interception, concurrency and idempotence coverage, browser/admin harnesses, WordPress 5.8 compatibility, WooCommerce classic and HPOS, migrations, privacy scanning and source-integrity checks.
- Independent review found no remaining material findings.
- Staging smoke testing of the legacy conversion and therapist interface was reported successful before release.

## Upgrade

- No database migration is required; `EVENTBRIDGE_DB_VERSION` remains 7.
- WordPress 5.8 and PHP 7.4 remain the minimum supported versions.
- Production upgrades should use the verified release ZIP and retain version 2.0.3 for rollback.
